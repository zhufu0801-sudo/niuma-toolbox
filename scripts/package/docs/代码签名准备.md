# 代码签名准备（只做准备，未购买证书、未实际签名）

## 为什么要签名

- 现在的安装包是 ZIP + PowerShell 脚本，不是 EXE。员工电脑上可能出现“来自网络的文件”提示；企业把执行策略设成 `AllSigned` 时，未签名脚本**根本无法运行**。
- 签名后，脚本被改过一个字都能被 Windows 发现，客户可以确认安装包确实出自你们。
- 内置的 `node.exe` 已经由 Node.js 官方签名，不需要再签；`Sign-Package.ps1` 会顺便显示它的签名状态。

## 选哪种证书（2026 年公开资料，价格会变，购买前请以官网为准）

| 方式 | 适合 | 大致费用 | 说明 |
|---|---|---|---|
| Azure Artifact Signing（原 Trusted Signing） | 美国、加拿大、欧盟、英国的公司；美国、加拿大的个人 | 约 9.99 美元/月 | **日本、中国的公司和个人目前不能用** |
| OV 代码签名证书 | 有营业执照的公司、个体户 | 日本国内约 5.5 万～11.5 万日元/年（另需硬件令牌约 1.6 万～2.4 万日元）；海外约 129 美元起 | 全球可买，自 2023 年起私钥必须放在硬件令牌或云端 HSM |
| EV 代码签名证书 | 同上，审核更严 | 日本国内约 6.5 万～17 万日元/年 | 微软 2024 年取消了 EV 直接免除 SmartScreen 警告的优待，**只为去掉警告不值得多花钱** |
| SignPath Foundation（开源项目免费） | 完全开源（OSI 许可证、无闭源组件）、用公开仓库自动构建的项目 | 免费 | 本项目内含 WPS SDK 许可文件等，需要先确认是否符合条件 |

无论 OV 还是 EV，新证书一开始都没有“信誉”，SmartScreen 提示要随着下载量慢慢消失。

**建议**：以日本公司名义买一张 OV 证书（客户主要是日本企业，证书上显示公司名更有说服力）；中国客户版可以共用同一张证书。

## 签名步骤（拿到证书以后）

1. 按 CA 的说明装好硬件令牌驱动，确认证书出现在“当前用户 → 个人”证书库，并带有“代码签名”用途。
2. 照常打包（`slim.mjs` 瘦身、写好 README），**签名必须是最后一步**。
3. 先演练：
   ```powershell
   .\Sign-Package.ps1 -PackageDir D:\OfficeToolbox-0.11.0-Windows-x64 -WhatIf
   ```
4. 正式签名（时间戳地址填 CA 提供的；不加时间戳，证书到期后签名就失效）：
   ```powershell
   .\Sign-Package.ps1 -PackageDir D:\OfficeToolbox-0.11.0-Windows-x64 -Thumbprint <证书指纹> -TimestampServer <时间戳地址>
   ```
5. 脚本会逐个检查签名状态，有一个不是 `Valid` 就报错，不要发布。
6. 重新压缩 ZIP，换一台电脑解压，右键脚本 → 属性 → 数字签名，确认能看到公司名。

## 以后可以再做

- 做一个真正的安装程序（MSI 或 EXE）并签名，比 ZIP + 脚本更像正式产品，企业也更容易用 Intune 等工具分发。
- 每次发布都用同一张证书签名，SmartScreen 信誉会累积。
